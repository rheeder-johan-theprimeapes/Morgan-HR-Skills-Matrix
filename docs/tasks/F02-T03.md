# F02-T03 — Assessments and evidence

State: verified

## Outcome

Employees and managers record independent dated assessments with comments/evidence and history.

## Prerequisites

[F02-T02](F02-T02.md)

Confirm required evidence types/limits and visibility with HR before live use. Follow feature acceptance gates in [the index](README.md).

## Boundaries

Self and manager assessments, assessment revisions and private evidence. No review submission state machine.

## Contracts

Consumes: Catalogue, resolved targets, person scope and private-file/audit rules.

Introduces: Separate assessment authors/types, explicit missing/N/A/zero states, protected evidence versions and historical retrieval contract. These are interface responsibilities; inspect actual code before choosing class names.

### Implementation plan

- Maintain separate Assessment heads for employee/skill/self-or-manager with an expected revision number. Each successful save appends an immutable AssessmentRevision with actor, date, explicit rated/N/A/unassessed state, rating/comment/evidence notes and snapshots of skill/level/target meaning. No averaging or overwrite of self ratings. Stale revisions reject without writes and retain form input.
- Employees write/read their own self assessments. Current reporting managers and explicitly scoped HR review administrators can read self/manager evidence; manager writes require a current reporting relationship or scoped HR review administration, excluding self. Raw manager assessments remain confidential from the employee until the approved safe review release in F05. Designated SLT uses submitted review snapshots later rather than raw draft assessment access.
- Extend current-state scope reads to use locking reads inside write transactions. Lock mutable subjects/catalogue context and recheck scope/status at save. File staging happens once outside retryable database work and is removed on failed saves; old evidence remains unchanged.
- Store EvidenceAttachment metadata/digests against the immutable revision on a dedicated private local evidence disk with no public serving. Download endpoints recheck current assessment visibility, verify the digest and audit the record ID; always use attachment disposition and nosniff. No replacement/deletion endpoints.
- Initial technical upload defaults are PDF/PNG/JPEG up to 10 MiB, plus evidence notes; HR must confirm live types/limits. Content/type/extension/size and safe output names are validated; no executable or active-content formats. Evidence-required skills need notes or a new attachment on a rated revision. N/A requires permission and a reason. Dates cannot be future.
- Build full-page assessment lists, edit forms with current definitions/targets, and revision/evidence history. Test independent authors, retained files, stale errors, zero/N/A/unassessed states, scope/actor forgery, confidential manager response filtering, upload rejection, digest failure and current download access. Verify focused SQLite/MySQL, analysis, Pint/build; F02 integrated review after matrix.

Relevant [specification](../specification.md) sections: 5, 6.

## Acceptance criteria

- Self and manager ratings coexist; a manager update preserves the employee rating and previous evidence.
- Forged actor/person IDs and unauthorised evidence downloads are rejected without data leakage.
- Invalid levels, required evidence gaps and stale edits yield clear errors without lost input or corrupted history.
