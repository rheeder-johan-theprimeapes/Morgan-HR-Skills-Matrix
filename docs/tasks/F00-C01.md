# F00-C01 — Fail closed for environment-derived development database names

State: verified

## Outcome

The MySQL test profile refuses to run when the normal development database identity cannot be independently established, including names derived from environment variables. It must reject a development target that could be the disposable test schema before providers or database-refresh traits run.

## Prerequisites

- [F00-T02](F00-T02.md), implemented and verified.
- Independent F00 review at commit `a2da616`: P1 database-isolation finding. Johan authorised this correction on 15 October 2026.
- Installed dependencies; a private explicitly isolated local MySQL test configuration for the engine check.

## Boundaries

Test-only parsing, the existing bootstrap safety guard, focused regressions and relevant repository evidence. Keep application/database configuration and private environment files unchanged. No business features, dependencies, commits or separate F00-C02 documentation-quoting correction.

## Contracts

Consumes the existing profiles, project TestCase bootstrap, `TestDatabaseSafety::assertSafe` and normal .env contents. Keep the existing cached-configuration, environment, test-name, local-host and URL/socket/read/write restrictions.

Introduce an independently testable contents-to-development-database parser in test support. Parse values without importing the PHPUnit-mutated process environment. For MySQL require a non-empty literal development DB_DATABASE, or a literal DB_URL with a scheme, host and non-empty decoded database path. Refuse URL query options because Laravel can use them to override the path. Any variable interpolation in the selected identity, missing identity or malformed source fails closed. Even references defined in the same file are refused: an externally supplied value could override their apparent file default. In-memory SQLite remains usable without a known development database identity.

## Acceptance criteria

- The review reproduction `DB_DATABASE=${DB_NAME}`, with DB_NAME externally supplied as morgan_hr_skills_test, cannot pass the MySQL isolation guard.
- Reject external/nested/same-file variable references, variable-derived URLs, unknown/blank identities and literal/encoded URLs naming the test database.
- Permit known separate literal names/URLs; preserve the in-memory SQLite profile and existing restrictions.
- Exercise parsing and the guard together without connecting to or changing a database. Malformed input errors must not disclose source contents.
- Bootstrap consumes the tested parser before provider/migration setup. Private .env files and the development database are unchanged.

### Changes and decisions

- Moved normal .env contents parsing into `TestDatabaseSafety::developmentDatabaseFromContents`, consumed by the existing bootstrap before providers/database-refresh traits. Read raw dotenv entries instead of resolving aliases against either file defaults or PHPUnit-mutated environment values.
- Require a non-empty independently literal development identity for MySQL. References (including same-file aliases), unknown identities and unsupported URLs fail closed. URL query options are refused because they can override the database path; encoded paths are decoded before comparison.
- Preserve in-memory SQLite, cached-configuration refusal, test-name/local-host restrictions and URL/socket/read/write safeguards. Malformed .env errors use a generic message without source contents or a chained source exception.
- Added 27 regression cases covering parsing plus the guard, externally supplied names, URLs, missing/blank identities, malformed input and successful literal/SQLite configurations. The external-value reproduction restores its process variable in a finally block. No regression test connects to a database.
- Updated the specification, quality guidance and task index. No dependencies, assets, application configuration or private environment files changed. No development database reset/migration, branch, staging, commit or push.
