## Contracts

Consumes: Scoped people, catalogue, assessment history/current ratings and shared target resolver.

Introduces: Authorised matrix query/filter contract and accessible full-page view with explicit coverage states. These are interface responsibilities; inspect actual code before choosing class names.

### Implementation plan

- A shared SkillsMatrix query applies EmployeeAccess before filters, uses bounded pagination, validates allowlisted department/role/group/skill/search/status filters and preserves the query string. Catalogue selector fields never widen people scope. Current employee and reporting-graph state drives every request.
- Preload grouped skill applicability, targets/levels and only permitted current assessment heads/revisions for the selected people/skills. Project scalar rows/cells; raw manager data is excluded for an employee and for organisation readers without assessment-review authority. No salary or internal narrative enters the matrix payload.
- Resolve every cell through TargetResolver::resolveFrom. Show separate self/manager state, ordinal, applicable target/source, formal manager gap and permitted self gap without averaging. Text explicitly distinguishes not applicable, N/A, unassessed, zero, missing target and restricted manager rating. Coverage counts use the same authorised cells.
- Build an accessible scrollable grouped-header table with sticky names, labelled filters, normal links/pagination, text alongside colour and keyboard-scroll focus. Use a bounded local fictional preview fixture for browser checks; never repoint/migrate the development database. The later F09 dataset expands the preview to complete journeys.
- Test tree and direct-identifier boundaries, forged filters, confidential response filtering, target gaps/coverage states, filter preservation and bounded query counts as cell count grows. Run full isolated profiles, analysis, Pint/build and independent F02 review. Record browser checks separately from automated tests.

Relevant [specification](../specification.md) sections: 5, 6, 11.

## Acceptance criteria

- Filters show correct permitted people/skills, targets/sources/gaps and separate ratings; navigation preserves context.
- Unauthorised people/pay data never enter page/Livewire payloads; manipulating filters cannot expand access.
- Missing/N/A/zero have distinct text; keyboard/mobile use and representative queries remain usable without per-cell N+1 loading.
