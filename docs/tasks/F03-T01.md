### Implementation plan

1. Add ScoringFramework with draft revision, predecessor, illustrative/approval metadata and JSON definition snapshots. Model events refuse published updates/deletion; no destroy route. Create factory and a guarded illustrative seeder for downstream fixtures.
2. Centralise definition validation/canonicalisation and catalogue snapshots. Form fields expose component weights, selected skills, rating points, required ratings/evidence and bands. Save drafts through a current-authority transactional action; publish validates complete monotonic mappings, active references and contiguous bands. Successors copy the immutable predecessor and retain lineage.
3. Write meaningful HTTP/action regressions first for authorised drafts/publication, invalid mappings/weights/bands/references, stale updates, immutable snapshots, forged access and successor isolation. Add ordinary full-page forms, read-only published detail and HR-only navigation.
4. Run focused SQLite/MySQL, analysis/Pint/build, then proceed to F03-T02. Independent feature review follows both tasks.

## Acceptance criteria

- HR edits a draft and publishes a validated version; revisions create a successor.
- Unauthorised publishing and mutation/deletion of a published version are refused.
- Non-monotonic points, invalid weights, ambiguous/gapped bands and invalid references are rejected; precision/band boundaries are documented.
