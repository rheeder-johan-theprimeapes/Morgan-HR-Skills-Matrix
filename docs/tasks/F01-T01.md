### Implementation decisions and plan

Goal: deliver native account provisioning, setup/recovery and sign-in using the existing Laravel 13 session guard and Blade. No new dependency or starter kit is needed.

- Create minimal `Employee` records with unique normalised `employee_number`, name and active status; F01-T03 extends these records with organisation fields. Each `User` has at most one employee through unique nullable `employee_id`, a unique normalised `login_id`, optional email, active status, narrowly scoped `can_administer_accounts` and an integer `session_version`. Existing scaffold accounts receive no administration grant.
- Create `AccountAccessToken` and `AccountAudit` records. Store only a SHA-256 digest of a random 64-character setup code, a 30-minute expiry and used timestamp. Audit only event/actor/subject identifiers, never credentials/codes. Issue codes privately in a no-store administrator response and accept them in POST bodies, keeping usable codes out of URLs/access logs and flashed input.
- `ProvisionAccount::handle(User $actor, array $data): User` creates the linked employee/account transactionally after policy authorisation. `IssueAccountAccess::handle(User $actor, User $subject): string` invalidates the prior code, clears native credentials and increments session version inside a subject-row lock; the console bootstrap creates the first administrator and issues access as that explicitly created actor. `CompleteAccountAccess::handle(string $loginId, string $code, string $password): void` rechecks active status/expiry/use under the same lock, consumes the code, changes credentials and audits use transactionally.
- Use thin session, setup and account-administration controllers, dedicated form requests, `UserPolicy` and an active-account middleware. Login/setup responses use a generic failure; login/setup are rate limited. Every protected request checks current account/employee status and session version. Passwords/codes are never flashed. Logout invalidates the session and regenerates CSRF.
- Add a console-only `app:bootstrap-account-admin` command that refuses when any administrator already exists, creates the explicitly supplied synthetic/real person only when deliberately invoked, and prints one private setup code once. Agent tests exercise it only in the isolated test database; do not run it against development or invent a real HR administrator.
- Use shared Blade layout/form components with accessible labels, errors, CSRF, ordinary navigation and no public registration. F01-T04 consolidates broader capabilities; account administration never implies salary access.

Execution steps: (1) add meaningful failing feature tests in `tests/Feature/PlatformAccountsTest.php`; (2) generate the required models/migration/actions/controllers/requests/policy/middleware/command through Artisan and implement the tested behaviour; (3) run the focused tests to green; (4) run Pint, analysis, complete SQLite and guarded MySQL profiles, and build; (5) record results and continue to the next eligible task after the feature review gate. Tests cover no-email setup/login/logout, denial of unprovisioned/disabled accounts, stale sessions, expired/replayed/reissued codes, unauthorised administration, privilege injection, generic failures, throttling, token secrecy and the bootstrap's one-time restriction.

Ruling: a private code entered on the setup page fulfils private setup/recovery access while avoiding bearer secrets in URLs. Cost if unsuitable: the handover UI can later add a separately reviewed delivery channel without changing token validation.

## Acceptance criteria

- A provisioned employee with no email sets credentials once and logs in/out successfully.
- Unknown/disabled accounts, expired/replayed setup codes and unauthorised provisioning/recovery are rejected; login responses avoid account enumeration. Access expires when expires_at is less than or equal to the current time, including the exact whole-second boundary.
- Throttling, CSRF/session handling and recovery do not expose usable secrets in logs or audit records.

### Changes and decisions

Added linked employee accounts with nullable email/password, separate narrow account-administration authority, expiring digest-only access codes, identity audit records, current-status/session-version enforcement, policy-authorised provisioning/recovery, a console-only first-administrator bootstrap and accessible Blade forms. Recovery clears credentials and invalidates sessions; codes are accepted only in POST bodies and never flashed or audited in usable form. The user factory keeps framework-free make() calls free of database writes; linked people are an explicit factory state. Security-record fixtures use factories/real issuance actions, not independent usable-token/audit seeders. EmployeeSeeder is local/testing-only and is not called automatically.

Ruling: setup uses a minimum 12-character passphrase and rejects values exceeding bcrypt’s 72-byte input boundary or containing NUL; login remains compatible with already provisioned credentials. Cost if policy changes: adjust the setup validation after HR confirmation. Existing scaffold accounts receive no person link or administration grant. Migration rollback deliberately refuses once native identities exist; use a reviewed forward recovery to preserve history.
