# F01-T01 — Platform accounts

State: planned

## Outcome

Provisioned employees can sign in/out, including employees without email, using private HR-issued setup/recovery access.

## Prerequisites

[F00-T02](F00-T02.md)

A designated initial HR/account administrator; synthetic employee IDs suffice in development. F00 feature acceptance. Follow feature acceptance gates in [the index](README.md).

## Boundaries

Native sessions, throttling, disabled-account handling and expiring single-use setup/reset access. No public registration or Microsoft flow. Keep provisioning authority narrow until F01-T04 consolidates permissions.

## Contracts

Consumes: Existing User/session infrastructure and quality commands.

Introduces: Stable account-to-person identifier contract, individual native credentials, controlled administrator bootstrap, reusable account-status checks and token-safe recovery audit. These are interface responsibilities; inspect actual code before choosing class names.

Relevant [specification](../specification.md) sections: 4, 5, 11.

## Acceptance criteria

- A provisioned employee with no email sets credentials once and logs in/out successfully.
- Unknown/disabled accounts, expired/replayed setup links and unauthorised provisioning/recovery are rejected; login responses avoid account enumeration.
- Throttling, CSRF/session handling and recovery do not expose usable secrets in logs or audit records.
