# F05-T03 — SLT decisions

State: verified

## Outcome

Authorised SLT compares HR-reviewed submissions and approves or returns recommendations safely.

## Prerequisites

[F05-T02](F05-T02.md)

Named decision makers/capabilities and final-decision fields confirmed with HR/SLT. Follow feature acceptance gates in [the index](README.md).

## Boundaries

Scoped decision comparison, approve/return with reasons and concurrency/audit. No automatic payroll or actual-pay update.

## Contracts

Consumes: Immutable submission revisions, HR-reviewed state and salary/approval capabilities.

Introduces: Final human decision bound to one revision, return lineage and approved payroll-change handoff data. These are interface responsibilities; inspect actual code before choosing class names.

### Implementation contract

1. Current person scope plus DecideReviews, ApprovePay and ActualPay are all required for the SLT queue, immutable revision inspection and decisions. The subject and assigned submitting manager cannot decide their own revision. Review administrators do not gain approval authority implicitly.
2. Append one immutable PdrDecision per immutable submission with actor, reason, approve/return outcome and explicit approved pay terms when approving. Change requires positive amount, currency, annual/hourly basis and effective date; no_change carries no invented amount. No automatic actual-pay update.
3. Lock the current head and require its optimistic version, current submission and HR-reviewed state. Approval advances to approved; return appends a reason and creates a separate draft copied from the locked source with submission lineage. Competing/duplicate decisions cannot both succeed.
4. A paginated scoped queue allows comparison of frozen score, proposal, actual pay and explicit units/dates. Human review is mandatory; no eligibility or pay decision is automated. Test permission combinations, self/manager exclusion, skipped HR/stale/cross-revision/duplicate decisions and unchanged pay, including committed MySQL interleaving.

Relevant [specification](../specification.md) sections: 5, 8, 9.

## Acceptance criteria

- An authorised decision maker approves/returns the current HR-reviewed revision with recorded reasons/outcome.
- Self-approval, insufficient salary/decision permission and skipping HR review are denied.
- Concurrent/duplicate decisions cannot both succeed or target a superseded revision; approval leaves actual pay unchanged.
