# F02-T02 — Targets

State: verified

## Outcome

Users see a consistently resolved target and its source for each applicable person/skill.

## Prerequisites

[F02-T01](F02-T01.md)

HR-approved individual exceptions and live target policy data; synthetic values for development. Follow feature acceptance gates in [the index](README.md).

## Boundaries

Role/department/individual target maintenance and precedence. No score or pay logic.

## Contracts

Consumes: Stable people, role/department membership, skill/rating definitions and policies.

Introduces: Shared target resolver: explicit approved individual override, else higher applicable role/department target; source and missing state. These are interface responsibilities; inspect actual code before choosing class names.

### Implementation plan

- Store one current SkillTarget per skill and department, job role or employee using restrictive foreign keys and unique scope indexes. The transactional SaveSkillTarget action validates the active skill/level/subject, records the approving HR actor and employee-visible exception reason, and audits changes. Updating or retiring a target preserves its ID; later review/assessment snapshots retain the then-current resolved values.
- ManageFrameworks grants target maintenance; individual exceptions additionally require current EmployeeAccess scope. Forms never accept an approving actor ID. Employees/managers can retrieve their scoped targets but cannot create exceptions.
- TargetResolver returns an explicit ResolvedTarget value: applicability, nullable ordinal/level ID, source, contributing target IDs and exception reason. An approved active employee target wins even when lower; otherwise higher department/job-role target wins with both sources on ties. Zero remains a real ordinal. Missing/retired/invalid targets are explained, never coerced to zero.
- Skills without applicability assignments are global; matching role/department includes a skill. An explicit approved individual exception may include an otherwise excluded person, while retired skills stay excluded. ResolveFrom consumes preloaded targets for matrix/scoring consumers to avoid per-cell queries.
- Build HR target forms and a scoped employee target page with visible provenance. Test all precedence/ties/missing/zero states, invalid levels/applicability, independent capabilities, direct-identifier denial and forged approval fields. Verify focused SQLite/MySQL, analysis, Pint and build; full F02 regression at its boundary.

Relevant [specification](../specification.md) sections: 6.

## Acceptance criteria

- All target sources resolve with visible provenance; an approved individual exception overrides a higher group target.
- Employees/managers cannot grant themselves an HR exception or modify unauthorised targets.
- Missing targets and invalid/inapplicable levels are explicit; repeated resolution is deterministic.
