## Boundaries

## Contracts

- Both PHPUnit profiles use a shared test bootstrap and an explicit profile constant selecting sqlite/mysql. Stop overwriting DB_DATABASE/DB_URL in XML so the bootstrap can observe their original inherited state.
- Capture only the names of inherited DB_DATABASE/DB_URL overrides from getenv, $_ENV and $_SERVER once, before Laravel loads any dotenv file. A missing snapshot or any inherited identity override (including an empty value) refuses MySQL; values/credentials are never stored in the snapshot or error output.
- After configuration loads, validate a fixed target for the selected profile and install it before providers: SQLite :memory: or the existing local morgan_hr_skills_test schema. Expose only that validated connection to database consumers, preventing other named connections from retaining development settings. The memory profile clears its URL; MySQL still refuses URL/socket/read/write overrides and requires private .env.testing.
- Keep literal development-identity requirements from C01. Compare its name case-insensitively to the disposable schema, conservatively refusing aliases even on a case-sensitive server. No MySQL metadata query is needed to decide safety.
- Cached configuration remains refused before loading; seed/generator settings and production configuration remain unchanged.

## Acceptance criteria

- Inherited DB_DATABASE=morgan_hr_skills_test cannot bypass a different literal .env name. Inherited DB_URL, including an empty value, is also refused for MySQL.
- Process regressions exercise the real MySQL profile and bootstrap using a test that never queries the database or runs migrations; rejection must have the intended generic message.
- Upper/mixed-case development names, including encoded URL paths, cannot pass the same-schema check.
- Clean isolated MySQL and memory SQLite still pass. In-memory SQLite tolerates inherited identity settings because the validated connection remains memory-only.
- Unknown/missing capture fails closed, original source precedence cannot hide an override, and repeated app boots do not mistake dotenv values loaded by the suite for inherited values.
- Keep all existing safety restrictions and tests. No development database reset or migration occurs.
