## Contracts

Consumes: Person scope, assessment evidence/private storage and audit conventions.

Introduces: Historical-document metadata, explicit visibility and authorised streaming/download contract. These are interface responsibilities; inspect actual code before choosing class names.

### Implementation contract

1. HistoricalDocument records one immutable private source file and provenance (employee, title, document date, source/reference, uploader, original safe name, size, MIME and SHA-256). It is explicitly unstructured history and never changes scores, releases or pay. Metadata/file replacement or deletion is not offered. Retention/purge policy remains a live HR gate; no automatic expiry is guessed.
2. Default visibility is HR only. Upload/visibility administration and HR-only retrieval require current scoped reviews.administer + pay.actual + context.sensitive because legacy files may contain unrestricted historical HR/pay material. Organisation view alone grants no file access. Additional explicit choices are current supervisors, or employee plus current supervisors; either requires confirmation that the entire file was reviewed for that audience and excludes internal calibration/comparisons and other people. Current person/reporting/account checks apply to every retrieval. No implicit employee release from upload.
3. Visibility changes append immutable actor/reason/time/confirmation revisions, with optimistic head version and current authority checked inside the transaction. Employee/supervisor views contain only currently allowed scalar metadata, never storage path/digest, private administrative reasons or hidden-document counts. Stale administrator input retains its original version for explicit reload.
4. Reuse private evidence disk and existing PDF/JPEG/PNG content+extension validation with maximum 10 MiB. Reject unsafe/control/path filenames; stage once at a known generated path outside retryable transactions; verify stored bytes before success. Failure cleanup removes only unreferenced files and preserves committed or uncertain references.
5. Full-page person document list and authorised download use a server allowlist, explicit visibility and historical labels. Download rechecks current scope, verifies size/digest and audits metadata, then streams as attachment/no-store/nosniff. Missing/tampered files fail clearly. No public storage URL exists.
6. Verify upload/provenance, visibility expansion/revocation and audit, guessed IDs/list privacy, employee/supervisor/organisation-only/disabled/revoked access, unsafe/oversize/missing/tampered files, stale changes, immutable history and storage/transaction failure cleanup, including current reads on isolated MySQL.

Relevant [specification](../specification.md) sections: 5, 10.

## Acceptance criteria

- Permitted users upload/retrieve a historical document with provenance and clear historical status.
- Direct storage URLs, guessed identifiers and visibility changes cannot expose files outside authorised scope; downloads are audited.
- Unsafe names/types, oversized files, missing storage and failed uploads leave no orphaned metadata or misleading success.
