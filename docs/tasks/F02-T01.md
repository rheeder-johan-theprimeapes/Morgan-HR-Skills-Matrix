### Implementation plan

- Introduce SkillGroup, Skill and SkillLevel with stable codes/IDs, active flags and restrictive references. Skill belongs to a group; levels have unique integer ordinals within a skill, labels and guidance. Rating meanings are append-only; retire a definition or introduce a successor skill rather than silently changing an existing level’s meaning. Future assessments/frameworks snapshot these definitions.
- Skill role/department applicability uses explicit many-to-many assignments. No assignments means applicable to all; matching either assignment includes the skill. An HR-approved individual target can explicitly include a person in F02-T02. No audience label grants access.
- Capability::ManageFrameworks is required for catalogue writes and administration. Account/directory authority alone is insufficient. Normal employees encounter applicable skills through their scoped assessment/matrix pages in later tasks.
- Use transactional SaveSkill/SaveSkillGroup/AddSkillLevel actions, validation in shared actions as well as requests for future import reuse, audit identifiers/changes, and no hard-delete route. Retired groups cannot accept new active skills; existing referenced definitions remain retrievable. Lock mutable referenced records before validation.
- Build full-page Blade catalogue/forms with reusable input components, labels and ordered rating guidance. Cover HR CRUD/retirement, role/department assignment, duplicate/malformed levels, forged writes and preserved rating meaning.
- Observe focused failures, implement and verify focused tests, Pint, analysis, guarded MySQL and build. F02 feature review follows T04.
