# F05-T04 — Feedback and acknowledgement

State: verified

## Outcome

Managers record feedback, release a safe approved outcome and employees acknowledge receipt or disagree.

## Prerequisites

[F05-T03](F05-T03.md)

HR-approved release wording/fields and permitted feedback recorder. Follow feature acceptance gates in [the index](README.md).

## Boundaries

Feedback record, explicit release, receipt/comment/disagreement and audit. PDF rendering belongs to F08.

## Contracts

Consumes: Approved immutable revision and human final pay decision.

Introduces: Reusable server-side employee-safe projection, release event and acknowledgment separate from agreement. These are interface responsibilities; inspect actual code before choosing class names.

### Implementation contract

- Append immutable feedback revisions against the exact approved submission/decision, with conversation date, employee-intended summary and development message. The current assigned supervisor or scoped review administrator may record/release; an administrator acting in place of the manager needs an explicit recorder reason. Neither may act on their own subject review. Feedback date cannot precede approval or be future-dated. Corrections before release append a new feedback revision and preserve history.
- Explicit release selects current feedback and the unchanged current approved revision, requires the head version and creates one immutable release. Its stored allowlist contains stable subject/cycle/framework labels, approved score/band, owned reflection, objectives, intended feedback/development and the human final pay outcome only. It never contains source context, manager calibration/proposal/rationale, actual-pay history, benchmarks, attachments or other people.
- A reusable EmployeeReviewSummary service owns safe generation and projection for HTML and later PDFs. The correct active employee may view the full released outcome; scoped staff may view only with ActualPay because the summary includes final pay. Managers/HR without salary permission can record intended feedback and release without receiving pay terms, then return to the review page.
- The employee may acknowledge receipt or disagree with an optional comment, once, against the current release/head version. Receipt never means agreement. Append immutable acknowledgement with actor/time/choice; it cannot mutate approved source, feedback, release or pay. Duplicate/stale release and acknowledgement return conflicts.
- Test pre-release/other-employee denial and complete view-data redaction, scope/grant changes, feedback corrections/chronology, release races, disagreement semantics and unchanged evidence/pay.

Relevant [specification](../specification.md) sections: 5, 9.

## Acceptance criteria

- Released outcome includes intended feedback/development/communicated pay; the correct employee can acknowledge receipt and comment.
- Before release or as another employee access fails; internal comparisons/proposals/calibration never enter HTML/Livewire payloads.
- Duplicate acknowledgement/release is safely handled; disagreement cannot alter approval/evidence or be treated as consent.
