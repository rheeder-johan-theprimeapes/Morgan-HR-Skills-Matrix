# F00-C04 — Refuse ambiguously quoted development identities

State: verified

## Outcome

The MySQL test guard refuses database identities whose remaining quotes can be normalised differently by Laravel, before providers or migration traits run.

## Prerequisites

[F00-C03](F00-C03.md). Independent agent review of `ce0c4e9` on 16 October 2026 confirmed a P1 using the installed dotenv parser/loader and Laravel environment resolver without database access. Johan's autonomous delivery instruction authorises correction and verification.

## Boundaries

Development-identity parser, database-free regressions and relevant evidence. No dependency, production configuration, private environment or development schema changes.

## Contracts

The dotenv parser removes one source quote layer, while Laravel's environment accessor can remove a remaining matching pair. Raw parser characters therefore are not a reliable literal identity when quote characters remain. Conservatively return unknown for an identity containing either quote character after parsing/URL decoding. Ordinary single-layer dotenv quoting continues to work. MySQL refuses unknown identity through the existing guard; memory SQLite remains usable.

## Acceptance criteria

- `DB_DATABASE="'morgan_hr_skills_test'"` and the reverse quote nesting cannot pass MySQL isolation.
- Ambiguous quoted separate names also fail closed; ordinary quoted separate names still pass.
- Existing inheritance, case, URL, local-host, cache and connection restrictions remain intact. No regression opens a database connection.

## Verification

Add cases to `tests/Unit/TestDatabaseSafetyTest.php`, observe them fail before implementation, then run `php vendor/bin/pest tests/Unit/TestDatabaseSafetyTest.php --compact`. Run Pint and analysis. Complete SQLite/MySQL profiles run after C05's independent service-isolation fix; retain each task's focused evidence separately.
